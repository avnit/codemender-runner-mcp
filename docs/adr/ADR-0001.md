# ADR-0001: Foundational Technical Stack, Build Tooling, and Engineering Conventions

* **Status:** accepted
* **Date:** 2026-10-08
* **Decision Makers:** CodeMender Maintainers

## Context and Problem Statement

We need to establish the foundational architectural blueprint governing the
repository's technical stack, build and packaging tooling, engineering and
testing conventions, and OpenSpec Specification-Driven Development (SDD)
process and domain organization across `codemender-runner`.

## Decision Outcome

Chosen option: Standardize on the foundational technical stack, build tooling,
engineering conventions, and OpenSpec Specification-Driven Development (SDD)
governance defined in this blueprint.

### Technical Stack & Packaging

* **Language & Data Models (`Python >= 3.11`, `dataclasses` or `attrs`):** All
  Python packages target `Python >= 3.11` and model domain data structures
  using standard library `dataclasses` or `attrs` alongside standard `typing`
  annotations.
* **Pragmatic Minimal Dependencies & Scoped Optional Extras:** Base runtime
  dependencies are kept minimal, but third-party libraries (such as `PyYAML` or
  `attrs`) may be added whenever they bring sufficient value. Heavy or
  target-specific SDKs (such as cloud provider or repository-host clients) are
  isolated in PEP 621 `[project.optional-dependencies]` scoped extras. Package
  root `__init__.py` modules export base interfaces and use lazy imports for
  optional target subpackages so base installs never raise
  `ModuleNotFoundError`.
* **PEP 621 Workspace & Build Backend (`[tool.uv.workspace]`,
  `setuptools.build_meta`):** A root `pyproject.toml` links workspace members
  under `packages/*` via `[tool.uv.workspace]`, and each package declares
  standard PEP 621 metadata built with `setuptools>=68.0`
  (`setuptools.build_meta`).
* **Build, Container, & Infrastructure Tooling (`Makefile`, Docker, Terraform
  `>= 1.5`):** A root `Makefile` drives unit testing (`make test`) and
  per-target `docker/*.Dockerfile` builds (using the repository root `.` as the
  Docker build context and installing packages into `/opt/codemender/venv`).
  Cloud infrastructure is provisioned with HashiCorp Terraform `>= 1.5` and
  validated with `terraform test` on `.tftest.hcl` suites.

### Package Layout & Testing Conventions

* **`src/<package>/` Layout & Domain-Driven Subpackages:** Each package uses
  the `src/<package>/` import layout and organizes modules into cohesive
  domain-driven subpackages without generic `common/` or `utils/` catch-all
  directories.
* **Colocated Unit Tests & Packaging Exclusions:** Unit tests live alongside
  the modules they test as `test_*.py` (discovered by `pytest` via `make test`)
  and are excluded from built wheels and container images via
  `[tool.setuptools.packages.find]` `exclude` (`test_*`, `*_test`, `testdata*`)
  and `.dockerignore`.

### SDD Process Rules

* All user-observable requirements and component contracts are documented in
  OpenSpecs (`spec.md` and `design.md`) under `docs/openspec/specs/`, and
  cross-cutting architectural decisions are recorded as MADR records in
  `docs/adr/`.
* Test Cases (`#### Scenario:` blocks in Given/When/Then format) must be
  defined before implementation, and implementation and test files carry
  `# Governing:` traceability comments pointing to their governing
  specification requirement anchors.

### Domain Organization

The following OpenSpec SDD domains under `docs/openspec/specs/` are in use and
organized as follows:

* **Journeys Domain (`journeys/`):** Contains critical end-to-end user and
  operator journeys (`sdd_level: JOURNEY`).
* **Tech Domain (`tech/`):** Divided into subfolders `tech/systems/`
  (macro-architecture, `sdd_level: SYSTEM`) and `tech/components/`
  (micro-architecture and bounded component contracts, `sdd_level: COMPONENT`).
* **Process Domain (`process/`):** The meta-domain that configures the OpenSpec
  SDD governance deployment (domains, levels, ID prefixes, allowed transitions,
  writing standard, review instructions, and templates). Isolated from the
  other domains; not for team, product, or runtime operational processes
  (`sdd_level: PROCESS`).

### Confirmation

Confirmed by running `pytest` via `make test` across colocated `test_*.py`
suites, `terraform test` on `.tftest.hcl` infrastructure suites, and OpenSpec
SDD verification checks auditing `docs/openspec/specs/` and `docs/adr/`.
